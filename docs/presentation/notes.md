### Де ламається локалізація: стрес-криві (2026-11-19)
`scripts/run_stress.py --area lviv_old_town`: 30 кадрів на точку, глобальний пошук по всій мапі без трекінгу
(порівнюються самі матчери), успіх = похибка < 5 px мапи (3.9 м). Фотометричні деградації накладаються на чисті
кадри, геометричні (висота, нахил) — перерендер із zoom-19 знімка, тож GT точний. Деградації детерміновані: усі
методи бачать ті самі зображення. Таблиця: `experiments/stress/lviv_old_town/summary.csv`.
Рисунки: `figures/4_stress_lviv_old_town.png` (криві), `figures/4_stress_lviv_old_town_examples.jpg` (як виглядають кадри).

| Деградація | SIFT | ORB | AKAZE |
|---|---|---|---|
| чисті кадри | 100 % | 87 % | 90 % |
| шум σ = 70 | 100 % | 80 % | 87 % |
| розмиття 30 px / 45 px | 97 % / 17 % | 67 % / 20 % | 87 % / 20 % |
| хмари 20 % / 40 % кадру | 97 % / 80 % | 60 % / 3 % | 3 % / 0 % |
| експозиція ×0.25 / ×0.12 | 43 % / 0 % | 83 % / 17 % | 0 % / 0 % |
| висота ×8 (кадр грубший за мапу) | 100 % | 90 % | 100 % |
| нахил 15e-4 / 20e-4 | 100 % / 83 % | 80 % / 60 % | 70 % / 20 % |
| час на кадр (CPU) | 35 мс | 450 мс | 52 мс |

- **Шум** не страшний нікому; **розмиття** до 30 px SIFT тримає, на 45 px (~11 px мапи) падають усі.
- **Хмари** — найсильніша деградація: SIFT тримає 40 % покриття, ORB — 20 %, AKAZE падає вже на 20 %
  (контрастні краї хмар забирають бюджет точок).
- **Темрява:** ORB живе найдовше (×0.25 — 83 %), SIFT падає на ×0.25, бо поріг контрасту абсолютний →
  кандидат на покращення: CLAHE / нормалізація яскравості перед екстракцією.
- **Висота:** кадри, ближчі за масштабом до мапи (×2–×6), прив'язуються навіть краще за ×1 (ORB / AKAZE 87–90 % → 100 %):
  дрібні деталі zoom-19 кадру, яких немає на мапі, лише заважають. Вибір `frame_scale` важливий.
- **Нахил:** знайдено й виправлено баг у `geometry.sanity_check` (PR #7): нахилені гомографії далеко від початку
  мапи відкидалися як `reflection`. До фіксу SIFT на найменшому нахилі давав 60 %, після — 100 %.
- Навчені методи (SuperPoint / LightGlue, XFeat, RoMa) — у Colab, на тих самих кадрах (`--plot-only` зводить усе на один графік).

### Порівняння методів (етап 5, 2026-11-20)
- Звіт: `experiments/map_report.md` (+ `.csv`), генерує `scripts/make_map_report.py` з
  `experiments/map_benchmark*.csv`. 60 конфігурацій, ~300 прогонів, 6 наборів.
- Рисунки: `figures/3_methods_accuracy.png`, `figures/3_methods_pareto.png`, `figures/3_ablation_<група>.png`.
- **Синтетика з GT (syn_hard, «знято з екрана»):** усі сильні методи 0.62–0.76 px медіанної похибки при 92.5% кадрів;
  найкращий SuperPoint+LightGlue 0.62 px, бейзлайн SIFT 0.73 px. 6 кадрів із 80 не реєструє жоден метод
  (найсильніші спотворення). AKAZE/BRISK глобально 0.31–0.33 px, але лише на 86–89% кадрів (медіана по легших).
- **syn_easy:** SIFT-трекінг 0.03 px, RoMa 0.05, SIFT+LG 0.06, DISK+LG 0.07, SP+LG 0.16, бейзлайн SIFT 0.35 px.
- **Реальні відео:** усі методи (крім зламаних) реєструють 100% кадрів; різниця лише в точності й швидкості.
- **Узгодженість без GT упереджена до SIFT:** f2f-гомографії рахує SIFT → SIFT-локалізація ділить з ними похибки.
  На syn_easy SP+LG має GT-похибку 0.16 px (бейзлайн 0.36), а узгодженість 0.42 px (бейзлайн 0.05).
  Перехресна узгодженість (`scripts/cross_consistency.py`, f2f від SIFT / SP+LG / LoFTR, метрика `cons_other` —
  лише «чужі» матчери): відрив SIFT скорочується (нове відео: SIFT 0.28, DISK 0.29, SIFT+LG 0.32, SP+LG 0.35 px),
  але не зникає. Кореляція Спірмена будь-якої узгодженості з GT-похибкою по методах лише 0.24–0.43 →
  вона міряє плавність, а не точність; придатна, щоб відсіяти зламані методи (> 1 px).
- **Зламані / обмеження:** Efficient LoFTR із `transformers` 5.23 — лише грубі відповідності (сітка 8 px, без
  субпіксельного уточнення) + примусовий ресайз 640×480 → 20–40 px; офіційний репозиторій zju3dv дає 0.09–0.12 px на
  тесті зсуву й нормальні результати (syn_hard 0.66 px). XFeat* — систематичний зсув ~1.5 px; tiny-RoMa ~1 px.
- **Швидкість (відео, RTX 5060 Ti):** навчені методи 0.3–3.4 fps проти 5.6–9 fps у SIFT по всій мапі (CPU).
  RoMa 0.1 fps, DeDoDe 0.06 fps.
- **Вибір:** SIFT + FLANN + ratio 0.75 + MAGSAC++ по всій мапі (= бейзлайн). 100% кадрів на всіх відео, без GPU,
  найшвидший; навчені методи точніші лише на частки пікселя на синтетиці, на реальних відео виграшу не видно.

### Абляції (syn_hard, медіанна похибка)
- **Деротація за прогнозом курсу** потрібна: без неї SIFT-трекінг 0.66 → 1.02 px, SP+LG 0.62 → 0.75 px, LoFTR
  0.70 → 0.78 px; без неї 70–85% кадрів знаходить лише глобальний SIFT (re-init). Перебір поворотів (`test`) повільніший
  у 3–4 рази і не точніший.
- **Масштаб кадру:** 0.25 → 0.46 px і 22 fps; 0.5 (база) 0.73 px, 7.6 fps; 1.0 → 0.91 px, 5.2 fps.
- **Оцінювач:** MAGSAC++ / RANSAC / USAC і поріг 2–8 px — різниця ≤ 0.03 px; на відео RANSAC гірший (SP+LG 0.29 проти
  0.12 px узгодженості).
- **Передобробка:** CLAHE, маска екрана, розмиття σ=1 — ±0.02 px; σ=2 гірше (0.78 px, 86% кадрів).
- **Пошук:** тайли замість одного FLANN-індексу — 1.02 px і 0.2 fps (гірше й у 40 разів повільніше).
- **Трекінг SIFT:** ROI 1.2 замість 1.6 — та сама точність, ~2× швидше на відео; ROI 3.0 повільніше; авто-масштаб і
  модель руху на цих відео майже нічого не змінюють.
- **Згладжування Savitzky–Golay:** вікно 7 → 1.02 px, вікно 15 → 11.5 px (стирає різкі повороти); без інтерполяції
  0.69 px. Висновок: не згладжувати.
- Ліцензія: ваги SuperPoint / SuperGlue (Magic Leap) — некомерційні.

### Парний бенчмарк із точним GT (`data/_finetune_pos_crops`, 2026-11-20)
- 7 послідовностей вирізок 512×512 з однієї орієнтованої на північ ортофотомапи; сусідні вирізки зсунуті на ціле
  число пікселів. GT зсуву — повний перебір усіх цілих зсувів через FFT + перевірка піксельного збігу (RMSE ≤ 5.5,
  унікальний мінімум) — без жодного матчера. 879/1050 пар валідні; послідовність 11 без перекриття — виключена.
- Скрипти: `scripts/make_pair_benchmark.py` (GT), `scripts/run_pair_benchmark.py` (методи),
  `scripts/make_pair_report.py` (звіт `experiments/pairs/finetune_pos_crops/report.md`, рисунок
  `figures/4_pairs_success.png`). Один оцінювач для всіх (гомографія, MAGSAC++, 3 px).
- Варіанти: `plain` (як є), `geo` (+ поворот ±15°, масштаб 0.75–1.3), `hard` (+ деградації «з екрана»).
  Порівняння на спільних 210 парах на варіант; DeDoDe / RoMa — окремо на 120 парах з еталонами на тих самих видах.
- `plain` — артефакт цілого зсуву: детектори на піксельній сітці (DeDoDe) дають 0.00 px; точність порівнювати на `geo`.
- Частка пар з похибкою ≤ 3 px (plain / geo / hard):
  SIFT+LightGlue 99 / 88 / 39 %; Efficient LoFTR (офіційний) 100 / 96 / 34 %; ALIKED+LG 98 / 83 / 34 %;
  DISK+LG 96 / 78 / 30 %; LoFTR 100 / 97 / 28 %; SIFT+FLANN 95 / 89 / 19 %; SP+LG 78 / 68 / 19 %;
  SuperGlue 75–80 / 64–65 / 12–14 %; tiny-RoMa 59 / 44 / 14 %; DeDoDe (120 пар) 100 / 95 / 38 %.
- Медіанна похибка на `geo`: SIFT 0.19–0.20 px (найточніший), LoFTR 0.41, SIFT+LG 0.44–0.49, eLoFTR 0.55–0.59,
  DISK 0.9, SP+LG 1.7 px.
- **Головне:** на `hard` SIFT+FLANN знаходить оцінку лише для ~40% пар, SIFT+LightGlue — для 84–88%; на полях з лісом
  (послідовність 05) 9% → 80%. Тобто слабке місце SIFT у складних умовах — матчинг (ratio test), а не детектор.
- SuperPoint тут слабкий навіть на чистих парах (медіана 1.16 px) — точки без субпіксельного уточнення.
- Швидкість на парі 512×512, GTX 1650: SIFT 170 мс, SIFT+LG 230–300, eLoFTR 188, LoFTR 345, SP+LG 85, XFeat 27,
  DeDoDe ~11 с (vast); GPU vast.ai була спільною і повільнішою за локальну.
