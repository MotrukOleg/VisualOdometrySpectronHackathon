# Нотатки для презентації

Ключові числа й спостереження по ходу роботи. Кожен запис має посилання на `run_id` із `experiments/summary.csv`.
Фінальні рисунки зберігати поруч, у `figures/`.

## Дані (2026-11-19)
- Мапа 3645×1845, 50 кадрів 640×640; масштаб кадр → мапа ≈ 0.25; крок ≈ 90 px мапи на кадр.
- SIFT + FLANN + MAGSAC++ по всій мапі: 50–180 inliers на кадр (розвідка, кадри 0/1/10/20/30/40/49).

## Експерименти

### Standard level — бейзлайн (2026-11-19)
Конфіг `configs/map/baseline_sift.yaml`: SIFT (кадр ×0.5, 4000 точок) + FLANN + ratio 0.75 + MAGSAC++ гомографія,
пошук по всій мапі (60 000 точок SIFT, 1.4 с), без трекінгу і згладжування.
- **50 реальних кадрів:** зареєстровано **50/50**, 0 відкинутих, 0 інтерпольованих; inliers 130 у середньому
  (медіана 134); 9.1 кадр/с; увесь прогін 11.5 с. Рисунки: `figures/1_route_standard_baseline.png`,
  `figures/1_route_standard_zoom.png`.
- **Узгодженість без GT** (`scripts/check_consistency.py`): рух кадр↔кадр проти позицій на мапі —
  розбіжність центру медіана **0.06 px**, максимум 0.12 px мапи (49 пар). Перевірка чутлива: штучний зсув одного
  кадру на 10 px дає 10.06 px.
- **Синтетичний політ над мапою з GT** (80 кадрів, масштаб 0.25, легка перспектива): 80/80, похибка центру
  медіана **0.35 px**, максимум 0.40 px, success@5px = 100 %. Рисунок: `figures/1_route_synthetic_gt.png`.
  Застереження: синтетичні кадри вирізані з тієї ж мапи → оцінка оптимістична.

~1/3 мапи; масштаб 0.48–0.65 px мапи на px відео (висота змінювалась ±15 %). Кольори вибілені екраном, є нахил,
в одному кадрі видно рамку монітора; сильно розмитих кадрів немає (дисперсія лапласіана 541–915).
- Той самий бейзлайн SIFT без змін: **206/206** кадрів прив'язано при frame_scale 0.5 / 0.35 / 0.25;
  inliers ~1100 (0.5), ~1070 (0.35), ~860 (0.25); 3.5–4.3 кадр/с.
- Маршрут — прямокутна петля, довжина 7070 px мапи; старт і фініш поруч (103 px):
  позиції абсолютні (від мапи), тому дрейфу немає.
- Узгодженість кадр↔кадр проти кадр↔мапа: медіана **0.02 px**, максимум 0.12 px мапи (205 пар).
- Рисунок: `figures/1_route_video0061_baseline.png` (контури кожного 6-го кадру).
- **Відео з поточною позицією** (`scripts/render_video.py`): 1920×1080, H.264, 1026 кадрів / 34 с; позиції між
  ключовими кадрами (кожен 5-й) інтерпольовано лінійно. Панелі: камера, збільшена мапа навколо дрона (north up) з
  контуром кадру, огляд маршруту з траєкторією, що наростає, і HUD. Рендер ~1 хв.
  Для слайдів: `media/2_video0061_position.mp4` (720p, 5.4 МБ), `media/2_video0061_position.gif` (560 px, 9.6 МБ).

### Advanced level — складне відео `IMG_0062.MOV` (2026-11-19)
iPhone, HEVC, **портрет 1080×1920**, 30 fps, 36 с (1073 кадри); кожен 5-й → 215 кадрів. Сильний нахил (кадри —
трапеції), у кадрі рамка монітора і стіл, розмиття в русі (дисперсія лапласіана медіана 271 проти 681 у IMG_0061,

- Бейзлайн SIFT без змін: **215/215** (frame_scale 0.5 і 0.35), 0 відкинутих / інтерпольованих.
  Inliers: медіана 664 (0.5), мінімум 81 (кадр 530). 3.7 кадр/с.

- Висновок для покращень: точності бейзлайну вистачає; слабкі місця — швидкість (3.7 кадр/с, пошук по всій мапі)

### Будь-яка місцевість: мапа з супутникових тайлів (2026-11-19)
`scripts/make_area.py --area <name>` (райони в `configs/areas.yaml`): мапа Esri World Imagery на zoom 17
(~0.77 м/px, 2.8×1.4 км, ≈ 3640×1820 px — як мапа із ТЗ) + та сама ділянка на zoom 19, з якої ріжуться кадри
640×640 (масштаб кадр → мапа 0.25, як у ТЗ). Кадри мають справжні дрібні деталі, яких немає на мапі, а не є
збільшеними шматками мапи. Політ 80 кадрів, точний GT у пікселях мапи + lat/lon (`geo.json`).
Застереження: де Esri не має zoom 19 (село, гори), кадри беруться з zoom 18 і збільшуються ×2.

Бейзлайн SIFT (`configs/map/baseline_sift.yaml`) без змін, CPU (MacBook):

| Район | Місцевість | Прив'язано | Інтерп. / втрачено | Inliers (медіана) | Похибка, медіана | success@5px |
|---|---|---|---|---|---|---|
| `lviv_old_town` | щільне місто | 80/80 | 0 / 0 | 141 | 0.33 px (~25 см) | 100 % |
| `carpathians` | ліс, гори, траси (z18) | 79/80 | 1 / 0 | 115 | 0.36 px | 100 % |
| `kyiv_dnipro` | місто + Дніпро | 57/80 | 17 / 6 | 150 | 0.37 px | 71 % |
| `poltava_fields` | поля (z18) | **23/80** | 54 / 3 | 65 | 759 px | **29 %** |

run_id (у тому ж порядку, що в таблиці): `map_baseline_sift_20261119-222450`, `-222518`, `-222500`, `-222547`
в `experiments/results/area_summary.csv`.
- Там, де є текстура (місто, ліс із просіками), SIFT точний і на чужій місцевості.
- **Вода:** над Дніпром кадр не має ознак → втрата; потрібен трекінг / VO, щоб «перелетіти» річку.
- **Поля:** однорідні й повторювані ділянки → прив'язка лише над селом; лінійна інтерполяція між рідкими фіксами
  дає маршрут навпростець через поле (похибка до 2224 px ≈ 1.7 км) → кандидати для навчених методів.
- Рисунки: `figures/4_area_{lviv_old_town,carpathians,kyiv_dnipro,poltava_fields}_sift.png`.

### GPS на виході (2026-11-19)
`scripts/export_gps.py --run <run> --geo data/areas/<name>/geo.json --gt .../gt.csv`: пікселі мапи → lat/lon через
Web Mercator (точно, без апроксимації) → `trajectory_gps.csv`, `route.geojson` (відкривається в geojson.io, QGIS),
`route_map.html` (інтерактивна мапа: супутник / вулиці Esri, клік на кадр — координати, курс, inliers, похибка в метрах).
Ті самі прогони SIFT, похибка відносно GT у метрах на землі:

| Район | Похибка, медіана | Максимум | В межах 5 м |
|---|---|---|---|
| `lviv_old_town` | 0.25 м | 0.35 м | 100 % |
| `carpathians` | 0.28 м | 3.4 м | 100 % |
| `kyiv_dnipro` | 0.28 м | 69 м | 73 % |
| `poltava_fields` | 588 м | 1723 м | 29 % |

Для порівняння: побутовий GPS дає 3–5 м. Там, де кадр прив'язано, візуальна навігація точніша за GPS.
Інтерактивні мапи для слайдів (вставляти через `<iframe>`): `media/4_area_*_route_map.html`.

### Де ламається локалізація: стрес-криві (2026-11-19)
`scripts/run_stress.py --area lviv_old_town`: 30 кадрів на точку, глобальний пошук по всій мапі без трекінгу
(порівнюються самі матчери), успіх = похибка < 5 px мапи (3.9 м). Фотометричні деградації накладаються на чисті
кадри, геометричні (висота, нахил) — перерендер із zoom-19 знімка, тож GT точний. Деградації детерміновані: усі
методи бачать ті самі зображення. Таблиця: `experiments/stress/lviv_old_town/summary.csv`.
Рисунки: `figures/4_stress_lviv_old_town.png` (криві), `figures/4_stress_lviv_old_town_examples.jpg` (як виглядають кадри).

| Деградація | SIFT | ORB | AKAZE |
|---|---|---|---|
| чисті кадри | 100 % | 87 % | 90 % |
| шум σ = 70 | 100 % | 80 % | 87 % |
| розмиття 30 px / 45 px | 97 % / 17 % | 67 % / 20 % | 87 % / 20 % |
| хмари 20 % / 40 % кадру | 97 % / 80 % | 60 % / 3 % | 3 % / 0 % |
| експозиція ×0.25 / ×0.12 | 43 % / 0 % | 83 % / 17 % | 0 % / 0 % |
| висота ×8 (кадр грубший за мапу) | 100 % | 90 % | 100 % |
| нахил 15e-4 / 20e-4 | 100 % / 83 % | 80 % / 60 % | 70 % / 20 % |
| час на кадр (CPU) | 35 мс | 450 мс | 52 мс |

- **Шум** не страшний нікому; **розмиття** до 30 px SIFT тримає, на 45 px (~11 px мапи) падають усі.
- **Хмари** — найсильніша деградація: SIFT тримає 40 % покриття, ORB — 20 %, AKAZE падає вже на 20 %
  (контрастні краї хмар забирають бюджет точок).
- **Темрява:** ORB живе найдовше (×0.25 — 83 %), SIFT падає на ×0.25, бо поріг контрасту абсолютний →
  кандидат на покращення: CLAHE / нормалізація яскравості перед екстракцією.
- **Висота:** кадри, ближчі за масштабом до мапи (×2–×6), прив'язуються навіть краще за ×1 (ORB / AKAZE 87–90 % → 100 %):
  дрібні деталі zoom-19 кадру, яких немає на мапі, лише заважають. Вибір `frame_scale` важливий.
- **Нахил:** знайдено й виправлено баг у `geometry.sanity_check` (PR #7): нахилені гомографії далеко від початку
  мапи відкидалися як `reflection`. До фіксу SIFT на найменшому нахилі давав 60 %, після — 100 %.
- Навчені методи (SuperPoint / LightGlue, XFeat, RoMa) — у Colab, на тих самих кадрах (`--plot-only` зводить усе на один графік).
