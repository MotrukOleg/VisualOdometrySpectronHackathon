# Роадмапа: навігація дрона за супутниковою мапою (It-Jim CV test task 2026, Advanced level)

## Постановка

**Standard:** є супутникова панорама району (`global_map.png`) і серія фото з дрона. Треба відновити й
візуалізувати маршрут, зіставивши кожне фото з мапою (класичні або DL-методи ознак і зіставлення).

**Advanced (наш рівень):** самостійно зняти відео: мапа на весь екран, телефон або вебкамера рухається над екраном,
імітуючи проліт дрона. Кадри відео зіставляються з мапою, траєкторія візуалізується.

**Обов'язкові вимоги:**
- код читає мапу і серію кадрів (або відео) із заданих шляхів;
- результат — одне зображення з траєкторією **або** відео з траєкторією й поточною позицією дрона в реальному часі;
- охайний, прокоментований код, `requirements.txt` / `environment.yml`, `README.md` з описом рішення;
- зображення мапи з маршрутом: позначено старт і фініш, видно порядок точок.

**Рекомендації із завдання (робимо всі):**
- експериментувати зі зменшенням масштабу зображень для кращого зіставлення;
- інтерполяція і згладжування траєкторії;
- відео з наближеною ділянкою мапи й покадровою траєкторією;
- контури кадрів на мапі зі збереженням їхнього розміру і повороту.

**Наша додаткова мета:** систематично порівняти детектори, дескриптори, матчери й оцінювачі; вибрати бейзлайн і
найкращу комбінацію за метриками; додатково склеїти кадри в мозаїку (VO між кадрами).

**Фінальний результат роботи:** презентація з результатами (етап 7), яку робимо після завершення всіх етапів.

## Порядок роботи (пріоритет, рішення від 2026-11-19; дедлайн — 2 дні)

1. **Standard level за вимогами завдання.** Мапа + 50 кадрів → маршрут на мапі з START/FINISH, порядком точок і
   контурами кадрів. Бейзлайн SIFT, інтерполяція й згладжування за потреби. **Зупинка: переглядаємо результат.**
2. **Advanced level.** Власне відео з екрана → той самий конвеєр → зображення маршруту + відео з поточною позицією.
3. **Покращення.** Навчені методи, трекінг, порівняння методів, абляції, мозаїка.
4. **Оформлення.** README, `environment.yml`, презентація reveal.js.

Етапи нижче — повний план. Під дедлайн із нього беремо лише те, що потрібно для кроків 1–4, у цьому порядку.

## Що відомо про дані (`data/train/`, розвідка 2026-11-19)

| Параметр | Значення |
|---|---|
| Мапа | `global_map.png`, 3645×1845, міська забудова, річка |
| Кадри | 50 шт., `crops/crop_0..49.png`, 640×640 |
| Масштаб кадр → мапа | ≈ **0.25** (кадр 640 px ≈ 160 px мапи) |
| Крок між кадрами | ≈ 355 px кадру ≈ 90 px мапи, перекриття сусідніх кадрів велике (>2000 inliers SIFT) |
| Ракурс | косий (видно фасади й тіні), інша зйомка і кольори, ніж на мапі → гомографія лише наближена |
| Маршрут | зліва направо через усю мапу: (320, 988) → (3427, 987) у пікселях мапи |
| SIFT + FLANN + MAGSAC (повна мапа) | 50–180 inliers на кадр, усі перевірені кадри знайдено; на цих кадрах масштаб 0.25–1.0 майже не впливає |

Висновок: стандартний рівень класичний SIFT уже розв'язує. Основна складність — **advanced-відео**:
- зйомка з екрана: муар, відблиски, розмиття в русі, перспектива, автоекспозиція;
- у кадр потрапляють рамка монітора і стіл;
- масштаб мапи на екрані невідомий;
- кадрів у 30–60 разів більше.

## Архітектура рішення

```
мапа ──► MapIndex (багатомасштабні тайли + кеш ознак)
                     ▲
кадр/відео ─► відбір кадрів ─► передобробка ─► [глобальна ініціалізація | локальний трекінг]
                (різкість)    (масштаб, blur,       │ пошук по всій мапі   │ ROI мапи навколо прогнозу
                               маска екрана)        └──────────┬───────────┘
                                                   зіставлення кадр↔мапа ─► MAGSAC++ гомографія
                                                               │
VO кадр↔кадр (вже є) ─► прогноз положення ─────────────────────┤
                                                               ▼
                                     граф поз: якорі на мапі + відносні ребра VO ─► оптимізація
                                                               ▼
                                     відсів викидів ─► інтерполяція ─► згладжування (Kalman + RTS)
                                                               ▼
                                     зображення маршруту + відео з поточною позицією + метрики
```

Світова система координат — **пікселі `global_map.png`**. Для кожного кадру зберігаємо:
- гомографію кадр → мапа;
- центр, контур (4 кути) і курс;
- кількість inliers і статус: `map` (знайдено на мапі), `vo` (виведено з VO), `interp` (інтерпольовано), `lost` (втрачено).

## Ризики і як їх зменшити

| Ризик | Захід |
|---|---|
| Повторювана міська текстура → хибні прив'язки | трекінг у ROI, перевірка узгодженості з VO, MAGSAC++, мінімум inliers |
| Косий ракурс, паралакс будівель | гомографія + більший поріг, локальні ROI, згладжування |
| Інша дата зйомки, кольори й тіні | grayscale/CLAHE, навчені ознаки (SuperPoint, ALIKED), LightGlue / LoFTR |
| Муар і розмиття у відео з екрана | зменшення масштабу + blur, відбір різких кадрів, VO для проміжних кадрів |
| Обмеження 4 GB VRAM | тайли мапи, fp16, `resize_long`, CPU-фолбек, за потреби Colab |
| Немає GT | синтетика над реальною мапою + ручна розмітка ключових кадрів |
